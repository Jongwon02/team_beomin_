# 작물 상세페이지 항목별 지역 특성 안내 문구

## 배경
사용자가 지역 선택 → 홈 추천 카드 → "자세히 보기"로 작물 상세페이지에 들어가면
`Beomin_web/CropAdvisor.dc.html`의 "📍 {지역} 맞춤 정보" 섹션에 온도·강수·일조·pH·
유기물·유효인산·EC 7개 항목의 점수 막대만 보이고, 각 항목이 실제로 이 지역에서
어떤 의미인지 설명하는 문구가 없다. 초보 귀농인이 "이 지역 온도가 왜 이 점수인지,
그래서 뭘 조심해야 하는지"를 바로 이해할 수 있게 항목마다 1~2문장을 추가한다.

## 데이터 특성 (왜 두 그룹으로 나누는가)
- **온도·강수·일조**: `data/scripts/clustering.py`의 6개 기후 클러스터 단위로 지역마다
  고정된 실측 평균값이 있다(아래 실측 표). 지역의 "실제 기후 특성"을 사실 그대로
  설명할 수 있다.
- **pH·유기물·유효인산·EC**: 흙토람에서 시군구 단위로 실시간 조회되는 값이라 클러스터
  6개로는 설명이 안 되고, 프론트가 원본 수치(예: pH 5.8)를 받지 않고 점수(0~100)만
  받는다(`backend/scoring/climate_normal_score.py`가 점수만 breakdown에 채움). 백엔드
  변경 없이 점수만으로 문장을 만든다.

## 설계
각 항목의 안내 문구 = (항목에 따라) **지역 사실 문장** + **점수 등급별 재배 조언 문장**.

### 1) 온도·강수·일조: 클러스터별 사실 문장 (고정, 6클러스터 × 3항목 = 18개)
`data/raw/climate_clustering_final_v3.csv`를 클러스터로 묶어 실측한 평균값 기준으로 작성:

| cluster | 온도(연평균/1월최저) | 강수(연간) | 일조(연간시간) |
|---|---|---|---|
| 0 중산간내륙형 | 11.3℃ / -8.8℃ | 1276mm | 2181h |
| 1 중남부저지대형 | 13.3℃ / -4.4℃ | 1362mm | 2200h |
| 2 고랭지형 | 8.9℃ / -10.3℃ | 1377mm | 2093h |
| 3 중부내륙형 | 12.8℃ / -4.7℃ | 1149mm(최저) | 2276h |
| 4 남부해안형 | 14.7℃ / -1.3℃ | 1586mm(최다) | 2305h(최다) |
| 5 도서형 | 15.0℃ / 2.0℃(최고) | 1549mm | 1990h(최저) |

이 표를 바탕으로 `CLUSTER_VAR_DESC[clusterId][var]`에 지역 사실을 자연스러운 한 문장으로
저장한다(기존 `CLUSTER_DESC`와 같은 위치·톤).

### 2) 7항목 공통: 점수 등급별 재배 조언 (동적, 7항목 × 4등급 = 28개)
기존 등급 경계(80/60/40, `NORMAL_GRADE_META`와 동일)를 그대로 써서 항목별 점수를
우수/양호/주의/위험 4단계로 나누고, 각 항목·등급 조합마다 조언 문장 템플릿을 만든다
(작물명은 `{cropName}`으로 치환). 예:
- 온도 우수: "{crop} 재배에 이상적인 온도 조건이에요."
- 온도 위험: "{crop} 재배에는 온도 조건이 많이 불리해, 시설(하우스) 등으로 보완하지
  않으면 어려운 지역이에요."
- EC 주의: "토양에 염류(EC)가 다소 쌓인 편이라, 관수량을 늘리거나 담수로 씻어내는
  관리가 필요할 수 있어요."

(전체 28개 문구는 구현 시 코드에 직접 작성 — 위 예시가 톤·형식의 기준.)

### 3) 최종 문구 조합
- 온도·강수·일조: `CLUSTER_VAR_DESC[clusterId][var] + ' ' + tierAdvice[var][tier](cropName)`
- pH·유기물·유효인산·EC: `tierAdvice[var][tier](cropName)` (지역 사실 문장 없음 - 점수
  자체가 이미 그 시군구의 실시간 조회 결과라 지역별로 다름)

### 4) 구현 범위
- **프론트엔드만 수정** (`Beomin_web/CropAdvisor.dc.html`), 백엔드 무변경.
- 새 함수 `normalBreakdownWithDescOf(breakdown, clusterId, cropName)`를 만들어
  상세페이지 전용(`regionBreakdown2`, 4473행 부근)으로만 적용한다. 홈 화면 카드의
  `breakdownItems`(4374행)는 이번 요청 범위가 아니므로(사용자가 "지역선택 후 …
  상세정보 들어갔을 때"로 명시) 기존 `normalBreakdownOf` 그대로 둔다.
- UI: 항목별 점수 막대(928~940행) 각 줄 아래에 `b.desc` 텍스트 한 줄 추가.
- 데이터 없어 항목이 제외된 경우(`excluded_variables`)는 애초에 breakdown에
  없으므로 자동으로 문구도 안 나온다(기존 동작 유지).

## 테스트 방법
- 로컬에서 서로 다른 클러스터에 속한 지역 2~3곳(예: 서귀포/도서형, 태백/고랭지형,
  구미/중부내륙형)을 선택해 작물 상세페이지에 들어가서, 7개 항목 문구가 각각 다르게
  나오는지, 점수 등급과 문구 톤(우수→긍정, 위험→경고)이 어긋나지 않는지 육안 확인.
- 자동 테스트는 없음(순수 정적 텍스트 매핑이라 스냅샷/단위테스트 불필요 — 기존
  `CLUSTER_CROP_COMMENT`도 테스트 없이 관리됨).
